Architecture Overview

Factory Inventory Management System

A demo full-stack inventory/order/spending dashboard: a Vue 3 single-page app talking over HTTP to a FastAPI backend that filters JSON fixture data in memory — no database, no build-time coupling between the two halves.

Vue 3 · Composition API Vite FastAPI Pydantic In-memory JSON — no DB Demo auth (mocked)

Tech Stack

Two independently-run processes, joined only by HTTP calls on localhost.

Frontend

Vue 3 SPA · served by Vite on :3000
  • vue ^3.4
  • vue-router ^4.3
  • axios ^1.6
  • @vitejs/plugin-vue ^5.0
  • vite (dev server / bundler) ^5.2

Backend

FastAPI app · Uvicorn on :8001
  • fastapi >=0.110
  • pydantic (request/response models) >=2.5
  • uvicorn (ASGI server) >=0.24
  • pytest + httpx (tests) dev
  • managed with uv pyproject.toml

Data Layer

Static JSON, loaded once at process start
  • 7 fixture files in server/data/
  • loaded into Python lists by mock_data.py
  • filtered per-request, in memory
  • no persistence — writes don't survive a restart

System Architecture

The browser never touches data files directly — every read goes through the FastAPI process, which holds the dataset in memory for the life of the process.

main.py reloads straight from the JSON files Client-only state useAuth · useI18n mocked, never hits :8001

Request & Data Flow

Walking a single filter change from click to re-rendered chart — the path every dashboard view follows.

1
User changes a filterTime Period, Warehouse, Category, or Order Status in FilterBar.vue.
2
Shared reactive state updatesuseFilters.js holds the four selections as module-level refs (a singleton composable), so every view reads the same filter state.
3
View calls the API clientThe active view (e.g. Dashboard.vue) calls api.js, passing getCurrentFilters() — any value left as 'all' is simply omitted.
4
Axios issues an HTTP GETe.g. GET /api/dashboard/summary?warehouse=SF-01&category=electronics to http://localhost:8001.
5
FastAPI filters in memoryapply_filters() and filter_by_month() narrow the in-memory list by warehouse, category, status, and month/quarter.
6
Pydantic validates the responseEach route declares a response_model, so the filtered dicts are coerced/validated before serialization.
7
Vue stores the result and derives the restRaw data lands in a ref (e.g. allOrders); computed() properties derive totals, chart series, and KPIs, and the template re-renders reactively.

Notable Design Choices

No database, by designAll datasets load once from JSON at process start into plain Python lists. It keeps the demo dependency-free but means any mutation is lost on restart — there's no write path back to disk.
Filters are a shared singleton, not per-component stateuseFilters.js and useAuth.js declare their refs at module scope (outside the composable function), so every component that imports them reads and writes the same state — a lightweight substitute for Vuex/Pinia.
Auth, profile, and tasks are fully mocked client-sideuseAuth.js hardcodes a single signed-in user and an in-memory task list. api.js does define getTasks / createPurchaseOrder-style methods, but main.py has no matching routes — those calls aren't currently wired up to the views.
Bilingual UI baked into the mock datauseI18n.js plus locales/en.js and ja.js drive not just labels but the mock user's name, task titles, and job title — switching language changes the demo persona, not just the chrome.
